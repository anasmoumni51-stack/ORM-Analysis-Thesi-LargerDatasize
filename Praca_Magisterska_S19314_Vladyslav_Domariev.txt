1. Introduction
Every day, approximately 328.77 million terabytes of data are generated worldwide [1].
Even after filtering out noise, around 70% of this data remains relevant and must be
stored-typically on the database side. This data supports various functions, including
seamless system-user interaction, employee data analysis and other operational activities.
In the modern era, managing such a massive and growing volume of data can no longer be
handled efficiently by a single monolithic database server.

To address this challenge, systems have evolved to distribute data across multiple
databases of different types. This approach enhances scalability, performance and
flexibility.

This master's thesis explores the use of various types of databases. It examines the
advantages and disadvantages of each database type, considering their suitability for
different tasks and data structures.
Key words: Database performance evaluation, Transactional operations (INSERT,
SELECT, UPDATE, DELETE), Relational Database Management Systems (RDBMS),
NoSQL Databases.

14

1.1

The purpose of the work
The primary objective of this thesis is to conduct a comparative analysis of two database
system architectures by implementing a unified database schema in two distinct ways. The
first approach involves deploying the entire schema within a single relational database
management system (RDBMS), specifically Microsoft SQL Server (MSSQL). The second
approach distributes the schema across multiple databases, each based on a different data
storage paradigm-namely Neo4j (graph database), MongoDB (document-oriented
database), MSSQL (relational database) and Memcached (in-memory key-value store).
The schema will be partitioned according to the specific strengths and optimal use cases
of each database system, from a data storage and retrieval perspective. The performance
of both architectures will be evaluated through the execution of a representative set of
queries, with key performance metrics such as query execution time, data consistency and
durability being measured and compared.

2. Concept of development
The development concept is based on implementing a unified database schema within two
different system architectures. The first architecture utilizes a monolithic relational databasespecifically Microsoft SQL Server (MSSQL). The second architecture adopts a multidatabase approach, integrating systems that follow diverse data modeling paradigms,
including relational (MSSQL), document-oriented (MongoDB), graph-based (Neo4j) and inmemory key-value storage (Memcached).

The process begins with the generation of synthetic data using structured SQL scripts tailored
to the predefined schema. This data is initially inserted into the MSSQL database to establish
a centralized baseline. Once the database is populated, the data is exported and redistributed
across the heterogeneous system, with each component database selected based on its
strengths in availability, access efficiency and storage optimization.

Following the implementation, the second stage involves collecting statistical metrics related
to query execution performance, evaluating transaction isolation levels and assessing data
durability within both system architectures. The final step includes a comparative analysis of
the collected results to determine whether a multi-database system offers significant
15

advantages over a monolithic approach. If such benefits are observed, the study aims to
identify and explain the contributing factors.

3. Technologies and tools used in work
3.1

Microsoft SQL Server

Microsoft SQL Server (MSSQL) is a relational database management system (RDBMS)
developed by Microsoft. It is a comprehensive, enterprise-class solution that supports the
Transact-SQL (T-SQL) query language, an extension of the SQL standard. MSSQL is widely
adopted in production, financial and business applications due to its scalability, reliability and
advanced data processing capabilities [2].
Key features of Microsoft SQL Server include:














ACID Compliance: MSSQL fully adheres to the ACID properties (Atomicity,
Consistency, Isolation, Durability), ensuring data integrity even in the event of system
failures.
Advanced Transaction Mechanisms: It supports transactions at the T-SQL level,
enabling operations such as commit, rollback and savepoints for precise control over
data changes.
Rich Data Type Support: The system provides a broad range of data types, including
integers, floating-point numbers, text strings, binary data, temporal types, as well as
spatial and hierarchical data structures.
Stored Procedures and User-Defined Functions: MSSQL allows the definition and
execution of business logic directly on the server side, enhancing both performance
and security of applications.
Security Features: The platform offers robust security mechanisms such as rolebased access control, authentication, data encryption (e.g., Transparent Data
Encryption) and integration with Windows Authentication services.
Replication and High Availability: MSSQL supports multiple replication models
(snapshot, transactional, merge) and high availability features like Always On
Availability Groups.
Integration with Analytical Tools: The system integrates seamlessly with Business
Intelligence (BI) tools such as SQL Server Reporting Services (SSRS), SQL Server
Integration Services (SSIS) and SQL Server Analysis Services (SSAS).

Due to its maturity and tight integration within the Microsoft ecosystem (e.g., .NET, Azure),
Microsoft SQL Server is frequently selected as the primary database platform for large-scale
enterprise projects. Despite being a proprietary solution, a free edition (SQL Server Express)
is available, facilitating the deployment and testing of smaller applications.
In the context of this master's thesis, MSSQL serves as the reference monolithic database
system, allowing for comparative analysis against a distributed database architecture based on
multiple storage paradigms.

3.2

Memcached

Memcached is a high-performance, distributed, in-memory key-value store designed for
caching frequently accessed data [3]. Originally developed by Danga Interactive for
LiveJournal, it is widely used in large-scale web applications to reduce the load on databases
and increase data retrieval speed. Memcached does not provide persistent storage, but instead
offers a volatile memory-based solution focused on fast data access and horizontal scalability.
Key characteristics of Memcached include:










In-Memory Storage: All data is stored in RAM, which significantly reduces access
latency compared to disk-based storage systems.
Key-Value Paradigm: Memcached operates on a simple key-value architecture,
where values can be arbitrary binary or serialized data objects and keys are unique
identifiers.
High Throughput and Low Latency: Due to its simplicity and memory-based
architecture, Memcached can handle millions of requests per second with submillisecond response times.
Distributed Architecture: The system is designed to be easily distributed across
multiple nodes, allowing applications to scale horizontally by adding more servers.
No Data Persistence: Memcached is a volatile store; data is lost upon system restart.
As such, it is typically used as a complementary component for caching rather than
primary storage.
Minimal Overhead: Memcached is lightweight and does not support complex query
capabilities or secondary indexing, making it highly efficient for specific caching use
cases.

In the context of this master’s thesis, Memcached is employed as a fast-access layer within
the distributed database architecture. It is used to cache frequently accessed data segments to
enhance query performance and reduce the load on primary databases.

Neo4j

Neo4j is a high-performance, open-source graph database designed to efficiently manage and
query data structured as nodes and relationships. Unlike traditional relational databases,
Neo4j uses the property graph model, enabling natural representation of highly connected
data. It is widely applied in domains such as social networks, recommendation engines, fraud
detection and knowledge graphs [4].
Key features of Neo4j include:


interrelated data.

Efficient Graph Traversal: Neo4j is optimized for traversing deep relationships,

6. Evaluation of functional differences
6.1

Time-to-Live (TTL) mechanism and expiration management in Memcached and
MSSQL

Memcached offers a built-in and highly efficient Time-to-Live (TTL) mechanism that enables
automatic expiration of each key-value pair. This functionality is particularly beneficial when
storing data structures such as authorization tokens and refresh tokens, which are inherently
associated with a limited validity period. The Time-to-Live feature allows these temporary
objects to be automatically removed from memory once their expiration time is reached,
eliminating the need for additional cleanup logic within the system architecture.
By contrast, Microsoft SQL Server does not natively support TTL-based expiration.
Implementing similar behavior requires custom development efforts tailored to specific
business requirements. A typical workaround involves the following steps:
1.

Schema Design: Introduce a dedicated “ExpiryDateTime” column in the table
to record the expiration timestamp of each token.

2.

Value Assignment: Assign expiration values either via a trigger that executes
upon INSERT or UPDATE operations. An alternative approach involves
implementing the logic directly within the application layer (e.g., backend
service), which may be preferable depending on the specific flexibility
requirements and performance considerations. It is important to note that
triggers can introduce overhead, potentially affecting query performance.

3.

Data Cleanup: Configure a SQL Server Agent Job to periodically remove
expired tokens by executing a DELETE statement based on the
“ExpiryDateTime”.

191

While this method achieves the desired outcome. It comes with additional infrastructural and
licensing considerations. The SQL Server Agent, which is essential for scheduled operations,
is only available in the Standard, Web and Enterprise editions of SQL Server. As outlined in
Microsoft's official documentation: “Editions and supported features of SQL Server 2019”
[10].
In contrast, Memcached is distributed under a completely free license and includes TTL
capabilities by default. Making it a more accessible and resource-efficient option for
applications that require frequent expiration of volatile data.

7. Summary
In this thesis, an analysis of relational database management systems (RDBMS) and NoSQL
systems was conducted. The primary objective of this study was to compare the performance
of RDBMS and NoSQL systems. The main distinction between NoSQL systems and
relational databases lies in their handling of transactional consistency: some NoSQL
databases partially relax the ACID properties, while others operate under the BASE model.

During the study, the following data management systems were tested: the RDBMS MSSQL,
and the NoSQL systems Memcached, Neo4j, and MongoDB. Each system was deployed on a
single machine. Tests were performed for four types of database operations: INSERT,
SELECT, UPDATE, and DELETE. For each operation type, four datasets of varying sizes
were prepared, containing 100, 1000, 10000, and 100000 records.

For each operation type and dataset size, 10 repeated tests were conducted to improve the
statistical reliability of the results. Thus, a total of 40 tests were performed for each operation
type across the four datasets.

The test results demonstrated that, under the considered configuration, MSSQL outperformed
Neo4j. For example, inserting 1000 records in MSSQL required 1749.5 ms, compared to
68528.1 ms in Neo4j. Memcached exhibited the highest performance among all tested
systems due to its in-memory data storage, achieving execution times close to O(1) with a
20% margin of error. However, Memcached cannot handle datasets larger than the available
RAM. MongoDB ranked second in performance, executing operations approximately 34%
faster than the corresponding operations in MSSQL.

All systems showed a decrease in performance as the dataset size increased. Based on these
findings, several directions for future performance comparison studies can be suggested.
The current testing was conducted on systems deployed on a single machine. To evaluate
scalability, tests should be performed on a clustered environment, which would also allow
testing with larger datasets.

The data schema used in the tests was relatively simple. Using a more complex schema could
highlight scenarios in which data processing in NoSQL systems-particularly those that do not
support complex analytical queries-is offloaded to the client application, whereas relational
systems natively support such queries.
